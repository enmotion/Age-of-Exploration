## 0. 结论摘要

现有技术路线**不需要更换**。`src/engine/babylon/ocean/` 已经在做正确的事：顶点着色器用波场位移网格，片元着色器用 `cross(dFdx(vWorld), dFdy(vWorld))` 从真实三角形求面法线。这正是 Babylon.js 里做低多边形水面的正解。

差距在于**面片语法（facet grammar）没有立住**，具体是三处缺失：

1. **网格是规则均匀格**（`CreateGround` 700×700 / 190 细分 = 3.68 m），没有抖动，因此面片呈规则菱形纹，缺少参考图的不规则"碎玻璃"感；
2. **没有逐面片随机化**。参考图里每个面片内部单色、片与片之间明度和色相跳变，白沫和碎金都以"整个面片"为单位出现——这需要面片 ID 量化，目前完全没有；
3. **碎金不是逐面片镜面反射**，而是一套与屏幕无关的 `sin` 格纹，所以出不了参考图那条朝向太阳的楔形暖色带。

同时有两处"做多了"需要收回：面法线仍与平滑法线混合（`facetStrength=0.82`）、并叠加了细节法线扰动（`detailNormalStrength`）。参考图里**没有任何法线贴图的痕迹**，这两项会把面片感糊掉。

目标不是"更写实的海面"，而是复刻参考图那套**低多边形面片语法**。

## 1. 参考图拆解

### 1.1 面片几何

见 `crops/hero-foreground-facets.png`、`crops/hero-sun-glitter.png`、`crops/wave-tiles.png`。

- **四边形为主的不规则网格**：面片多为不规则的四边形，边缘是长而直的线段，面片之间无缝铺满，网格拓扑连通。不是三角形汤，也不是规则格纹。
- **面片尺寸**：hero 图中前景面片在世界空间约 **1–2 m**。换算到屏幕：常规航行视角（相机高 8–18 m、FOV 55–65°）下，1440p 前景单个面片约 **50–90 px**。
- **每片单色**：面片内部完全无渐变，片与片之间是硬边跳变。
- **浪脊是硬边折线**：脊线由若干面片边组成，迎光侧有一条**细亮边**（rim，约 1–2 px），背光侧立刻转入暗面——这是海浪"有厚度"的关键读感。
- **板块感**：浪瓦片（`wave-tiles.png`）显示每个模块是**带厚度的立体板**，能看见侧面墙，侧面比顶面暗一档。hero 图里浪尖也是这样"像一块板"。
- **平台浪尖**：大浪顶部有一段接近水平的面，再硬折下来；部分大浪有前倾的唇口。

## 2. 实现规格（Babylon.js / GLSL）

### 2.1 保留的路线，以及为什么它是正确的

```
顶点：base = position.xz → 波场位移 → 世界坐标
片元：faceNormal = normalize(cross(dFdx(vWorld), dFdy(vWorld)))
```

理由：

- 面法线来自**真实三角形**，所以屏幕上的面片与网格面片严格一一对应，不会出现"贴图法线伪造面片"导致的密度不一致。
- 位移在 GPU，同一套解析波场函数可在 CPU 侧复算，船体浮力与相机取高度**无需回读 GPU**。
- WebGL 没有 geometry shader，也不该为此引入后处理；这是唯一干净的做法。

**必须收回的两项**：

- 不要 `mix(smoothNormal, faceNormal, facetStrength)`——`facetStrength` 默认拉到 1.0，即**只用面法线**。
- 不要叠加 `detailNormalStrength` / `normalScaleX` / `normalScaleZ`。参考图无法线贴图痕迹。

### 2.2 抖动网格

网格改为**抖动的四边形格**：

```glsl
// 顶点着色器
vec2 base = position.xz;                     // 未变形的格点坐标
vec2 cell = base / cellSize;
vec2 offset = (hash2(cell) - 0.5) * jitter * cellSize;   // jitter ≈ 0.35
vec2 surface = base + offset;                // 抖动后的水平位置，再叠加波场位移
vCellCoord = cell;                           // 传给片元，用于面片 ID
```

要点：

- 抖动**只作用于渲染位置**，`base` 保持规则格点；
- `jitter ≤ 0.35`，保证四边形不自交、拓扑稳定；
- 对角线方向按面片 hash 交替，破坏对称；
- 目标面片尺寸 1–2 m（1440p 前景 50–90 px），这个值需要在实际镜头下试出来。

### 2.3 面片 ID 量化（核心技术）

#### 2.3.1 什么叫"面片 ID"

先澄清一个容易误解的点：**这里的"ID"不是随机数，是编号**，而且海浪每帧都在动并不影响它。

海面是一张网格，每个四边形/三角形就是一块"面片"。这张网格的**拓扑是固定的**：第 4821 号面片永远是第 4821 号，永远由同样的几个顶点构成。每帧变化的只是这些顶点的**高度**（以及很小的水平位移）。所以面片有稳定的身份。

"量化"就是把这个身份算出来——把连续的世界坐标变成离散的格号：

```glsl
vec2 cell = floor(vBase.xz / cellSize);   // floor 就是量化器
float fid = hash(cell);                   // 编号 → 一个固定的伪随机值
```

`hash` 是**伪随机**函数：看起来是随机数，但是纯函数，同样的输入永远给同样的输出。现有着色器第 136 行已经在用它了。

关键点：**格号只取决于面片在地面网格里的位置，与浪高、时间无关**。所以海浪怎么翻涌，`fid` 都不变，颜色不会闪。

#### 2.3.2 你现在的代码里已经有这个技术了

`shaders.ts` 第 169–170 行：

```glsl
vec2 patchCell = floor((vWorld.xz + time * patchSpeed) / max(.1, patchScale));
water *= 1.0 + (hash(patchCell) - .5) * patchStrength * colorPatches;
```

`floor(...)` 就是量化，`hash(patchCell)` 就是逐格稳定随机值——**技术完全一样**。唯一的差别是格子大小：现在 `patchScale` 是几米到几十米的自由值，**和真实网格面片无关**，所以它产生的是浮在水面上的方形色斑（这就是截图里那种"斑点感"的来源）。

把格子尺寸设成与网格面片一致、并让格点与网格对齐，它就变成"面片 ID"了。

#### 2.3.3 对齐与不对齐的差别

见 `images/facet-id-explained.png`：

- **①** 抖动网格里每个四边形有自己的格号 `(i,j)` 和固定随机值 `hash(i,j)`；
- **②** 取色格与面片格一致 → 每个面片整片一个颜色，色块边界与面片边界重合，就是参考图的效果；
- **③** 取色格错开半格 → 每个面片被切成两三个色块，出现横切面片的色斑。

> 注意：平移**整数**个格子仍然是对齐的，必须错开**非整数**格（如半格）才会错位。这一点在实现时容易踩坑——格子尺寸差一点点，效果就从 ② 塌到 ③。

#### 2.3.4 为什么必须精确对齐

抖动只改渲染位置，`base` 仍是规则格点，所以每个三角形在 base 空间恰好落在单位方格内，且**三角形内的世界坐标是 base 的仿射函数**（三个角各自加常量偏移）。仿射映射保持重心坐标，因此：

> 片元里对插值得到的 `vBase` 取 `floor(vBase / cellSize)`，与真实面片**逐一对应**，无误差。

```glsl
// 顶点
varying vec2 vCellCoord;   // = position.xz / cellSize
varying float vCellSize;   // 该环的 cellSize（三角形内恒定）

// 片元
vec2 cell = floor(vCellCoord);
float fid = hash(cell);        // 每面片一个稳定随机值 [0,1)
```

`fid` 驱动三件事：

```glsl
// 1) 逐面片明度/色相抖动
water *= 1.0 + (fid - 0.5) * facetValueJitter;      // jitter ≈ 0.16

// 2) 逐面片碎金阈值 → 整片金色面片
float glint = step(glintThreshold, spec * (0.6 + fid * 0.9));

// 3) 逐面片白沫块状侵蚀（替代 fbm 平滑噪声）
float shards = step(foamBreakup, fid);
foam *= mix(0.6, 1.0, shards);
```

**注意**：LOD 多环时，各环 `cellSize` 必须是 2 的幂（1 / 2 / 4 / 8 …）并共享格点原点，这样各环网格互相嵌套，`fid` 图案跨环连续，不会在环边界出现花纹接缝。

#### 2.3.5 稳定性依赖的两个前提（"海面是随机的"这个担心的真正风险）

面片编号本身是稳定的，但下面两件事做错了就会导致抖动/游动，必须在实现时守住：

1. **网格重定位必须按格吸附**。现有着色器有 `followCamera`（网格跟随相机移动）。如果网格原点连续滑动，世界坐标 `vBase` 就会连续滑动，`floor` 的结果会在格边界反复跳变，逐面片花纹就会**满屏游动闪烁**。做法是把网格原点吸附到 `cellSize` 的整数倍。
2. **水平位移必须小于半格**。Gerstner 波有水平方向的挤压位移（现有 `horizontalScale` / `chop`），如果挤压量超过半个格子，面片会越过自己原来的格号，`floor` 判定随之跳变。现有实现里 `chop` 乘的系数是 `0.34`，需要在 1–2 m 的格子下重新核算上限。

另外有一个实现细节需要视觉验收后定：网格是四边形、每格拆成两个三角形。按**四边形格**取 `fid` 会让一格的两种颜色一致，但两个三角形的真实面法线仍略有差异，可能出现一条很淡的对角线。参考图的面片本身也能看到内部分割，所以更可能应该保留；若验收时发现突兀，再改成按三角形取 `fid`（需要对对角线方向做一次侧判定）。

### 2.4 浪形尖化

现有 9 波（3 频带 × 3 交叉波）正弦叠加给出的是圆滑浪峰，与参考图的平台浪尖不符。需要：

- **尖化**：对归一化高度做非线性重映射，例如 `h = sign(h) * pow(abs(h), sharpen)`，`sharpen < 1` 使波峰变尖、波谷变平；
- **平台顶**：对位移后的高度做软上限（`clamp` 到平台高度附近），得到水平顶面；
- **前倾**：加大峰前的水平位移非线性（复用 `largeHorizontal` / `mediumHorizontal`），形成唇口；
- 保留现有"按距离淡出高层波"的能力，用于远近层次。

### 2.5 面片级光照与色阶

```glsl
float ndl    = dot(faceNormal, -sunDirection);
float light  = clamp(ndl * 0.52 + 0.52, 0.0, 1.0);
light        = clamp(light * shadingContrast + shadingBias, 0.0, 1.0);
light        = floor(light * steps + 0.5) / steps;   // steps ≈ 4（硬档位，不做过渡）
```

- `toneSteps` 默认从现有 7 降到 **4–5**，`toneTransition` 归零（参考图是硬档位）；
- 色阶按实测值重设四段：`valleyColor #012a4b` → `waterColor #0b537a` → `slopeColor #1b6e96` → `crestColor` 亮青；
- 逐面片明度抖动 ±8%；
- 浪脊迎光侧加细亮边（用 `fwidth` 做 1–2 px 常量宽度，避免远处糊成一片）。

### 2.6 白沫

- 遮罩信号沿用现有 `max(crest_i * weight_i - bias_i) + 高度 + 坡度`；
- **块状化**：把 `fbm` 换成面片量化 + 二级小格量化，得到参考图的块状与碎晶两种尺度；
- **两档明暗**：受光 `#e2dbdc`、背光 `#85a6c0`，用 `ndl` 分档选取；
- **底缘透光**：白沫下缘加 `sssColor` 的绿白辉光；
- **接触白沫**（阶段 7）：需要新增障碍物距离场输入（礁石 / 岛岸 / 船体），当前引擎没有此输入。

### 2.7 碎金楔形带

```glsl
vec2 sunAz   = normalize(-sunDirection.xz);
vec2 rel     = vWorld.xz - cameraPosition.xz;
float along  = dot(rel, sunAz);                              // 沿太阳方位
float lateral= abs(dot(rel, vec2(-sunAz.y, sunAz.x)));       // 横向偏移
float width  = glitterWidthNear * smoothstep(0.0, glitterRange, along);
float band   = 1.0 - smoothstep(width * 0.6, width, lateral);

vec3 reflected = reflect(-viewDir, faceNormal);
float spec     = pow(max(dot(reflected, -sunDirection), 0.0), highlightSharpness) * band;
float sparkle  = step(glintThreshold, spec * (0.6 + hash(cell * 3.1) * 0.9));

water += glitterColor * sparkle * highlightStrength;   // glitterColor ≈ #f4e2c5
```

- 碎金颜色必须用**暖白**（`#f4e2c5` / `#e4d2c1`），实测已确认；
- 密度用二级 hash（`cell * 3.1`）产生远处更密的读感；
- 低太阳角时带更宽更亮，正午收窄。

### 2.8 尾迹

- 现状是平面 ribbon + `StandardMaterial`，完全不受波场调制；
- 目标：复用 `evaluateOcean`（`wakeVertex` 已经这么做了）让泡沫贴合波面，颜色走**块状白沫规则**并逐面片打散；
- **转向弧线**：`wakeMaxPoints` / `wakeSampleDistance` 参数已存在，改为记录船长历史位置、沿路径生成 ribbon，而不是按当前朝向的直线；
- 高速时加宽、泡沫块变大，对应参考图的四级形态。

### 2.9 大气与地平线

- 新增去饱和混合：`mix(water, hazeColor, smoothstep(hazeStart, hazeEnd, dist))`，`hazeColor ≈ #7e9bb6`；
- 现有 `fogColor` 可复用，但参考图的雾是**偏亮的蓝灰**，不是深色。

### 2.10 网格与 LOD

单张 700×700 / 190 细分（3.68 m 均匀格）无法同时满足"近处 1–2 m 面片"和"地平线足够密"。建议：

- 以相机为中心的**同心环网格**，环宽按 1.0 / 1.5 / 2.2 / 3.3 … 递增，各环独立 `cellSize`（取 2 的幂）；
- 相机移动时按格对齐重定位，避免抖动游动（现有 `followCamera` 已具备跟随基础）；
- 船体附近额外保留一个高密度小块，避免大面片削弱船与浪面的视觉贴合。

## 3. 参数契约

### 3.1 现状

- 面板可见控件：**74 个**（`oceanControls.ts` 中 73 个 helper 调用 + 1 个 `fogMode` select）；
- 域类型 `OceanSettings` 实际有 **181 个键**（含 FFT 模块遗留键），面板只暴露其中 74 个；
- `tests/browser/initialization.spec.ts` 与 `oceanControls.test.ts` 强断言控件数为 74。**任何增删控件都必须同步更新这两处测试与 README**，且不能出现挂空控件。
- 控件计数不再硬编码在渲染器里：`data-active-controls` / `data-inactive-controls` 由 `App.vue` 从控件清单派生，渲染器只负责绘制。
- 命名不一致（历史遗留，建议本次一并清理）：面板 `valleyColor` → uniform `deepColor`；面板 `waterColor` → uniform `midColor`。

### 3.2 本次改动对参数的影响

**保留（语义不变，仅改默认值与范围）**
折面强度、明暗色阶、明暗对比、四个水色、饱和度、亮度、浪峰透光、反光颜色/强度/锐度、碎金尺度/阈值、白沫全部、尾迹全部、雾全部、太阳与昼夜相关。

**默认值变化**
`facetStrength` 0.82 → **1.0**；`toneSteps` 7 → **4–5**；四个水色按 1.2 实测色板重设。

**已实现**
`facetResolution`（网格细分，每边段数）—— 新增「海面网格」分组。海面平面固定 700 × 700 米，面片数 = 细分²，顶点数 = (细分 + 1)²，面片边长 = 700 ÷ 细分。控件摘要实时显示这三个派生量。它替代了原先设想的 `facetSize`（两者互为倒数关系，直接暴露段数更直观且便于网格对齐）。
实现要点：网格重建在主线程上有成本（实测 512 段约 22ms 掉帧），而拖动滑杆的 `input` 事件远密于帧率，因此**必须节流**——按代价分档，低细分 90ms、高细分 220ms，并保证尾部重建，最终值一定落地。

**建议新增控件（需同步改面板与测试断言）**
`facetJitter`（面片抖动）、`facetValueJitter`（面片明度抖动）、`glitterWidth`（碎金带宽度）、`glitterRange`（碎金带长度）、`hazeStrength`（空气透视强度）。

**建议移除的着色器 uniform（注意：这几项本来就未在面板暴露，只是 uniform）**
`detailNormalStrength`、`normalScaleX`、`normalScaleZ`（参考图无法线贴图）；`toneTransition` 改为恒 0 或直接删除（面片要硬边）。这几项不涉及面板控件数变化，因此**不影响 74 的断言**。

> 只有"建议新增控件"这一条会改变控件数量，届时 74 需变为 79，并同步更新 `oceanControls.ts`、两处控件数测试与 README 的描述。

**待决策**
`resolution` / `lambda` / `localFetch` / `swellFetch` / `steps` 等 FFT 遗留键的去留（与 `src/engine/babylon/fftOcean/` 是否保留一同决定）。

## 6. 风险与开放问题

**风险**

1. **面片量化与网格抖动的一致性**是成败关键。2.3 的仿射论证成立的前提是"抖动只改渲染位置、`base` 保持格点"，实现时不能为了省事直接对 `vWorld` 取 `floor`，否则面片边界会出现错位色条。
2. **大面片与船体贴合**：船体浮力用解析波场计算，不受网格影响，但视觉上大面片会让船与浪面出现穿插。需要在船体附近保留高密度小块。
3. **参考图有相当一部分是绘画笔触**（浪脊亮边、喷溅飞白、云的画法）。这些无法 1:1 程序化复刻，需要在阶段 3/4 明确哪些必须程序化、哪些接受近似。
4. **控制面板继续膨胀**：74 个控件再加 5 个，分组需要重构，否则面板会失控。
5. **多环 LOD 的 cellSize 接缝**：必须用 2 的幂且共享原点，否则逐面片花纹会在环边界出现接缝。

**开放问题（需要你决定）**

1. `风格化色阶 stylized` 开关是否保留？参考图没有写实模式，这个开关会变成"两套风格"。
2. `src/engine/babylon/fftOcean/`（约 4000 行、未被引用的 WebGPU FFT 海洋移植）是否保留？它会影响 `OceanSettings` 里那批 FFT 遗留键的去留。
3. 近岸浅水系统（阶段 7）需要岛屿/水深数据，是否现在就做，还是等玩法阶段一起？

参考图取 hero 水面区域，当前渲染取画面下方近中景水面区域，各做主色聚类与明度分布。

### 阶段 3 · 白沫与浪形

| 指标                | 参考图                 | 当前渲染               |
| ------------------- | ---------------------- | ---------------------- |
| 白沫覆盖率（Y>190） | 6.2%                   | 6.0%                   |
| 近纯白（Y>235）     | 2.4%                   | 3.3%                   |
| 白沫主色            | `#eddbc7` Y221（6.8%） | `#d9e0df` Y222（7.3%） |

两个关键修正：

1. 白沫原先被面法线光照压暗——浪脊面片是倾斜的，`lighting` 到不了 1，白沫被混进暗蓝背光色而呈**土黄块**。
   白沫是自发漫反射白体，现改为受光面趋近纯白、背光面只略冷略暗。
2. 浪脊信号减去阈值后最大只有 0.18，远低于 `foamBreakup`，所以真正出白沫的几乎只有碎晶项；
   阈值已按实测重新标定。

浪形增加了软饱和（`plateau`），把正弦压成平顶浪；坡度用的是该曲线的解析导数，保证与高度一致。

### 阶段 4 · 楔形碎金

调试过程中修掉三个量纲/逻辑错误：

1. 带宽原为 `glintScale * 6` ≈ 1 米，在 700 米场景里不到一个像素；
2. 带宽用饱和型渐开，几十米宽就把近中景整片盖住（用 `band` 可视化确认），
   参考图光路在屏幕上近似等宽，对应世界空间应**随距离线性张开**；
3. 沿用旧代码用 `glintAngle`（默认 18°）旋转了光路方位，正好把它从太阳方位转开。
   `glintAngle` 已移除（它本就不是面板控件）。
4. 碎金原用加法叠加，大面积下直接过曝成白斑；改为把水面推向暖金色。

| 指标  | 参考图 | 当前渲染 |
| ----- | ------ | -------- |
| Y>190 | 6.2%   | 9.3%     |
| Y>235 | 2.4%   | 3.9%     |

碎金偏亮一点，且默认视角下光路有一部分落在右侧控制面板之后（太阳方位在画面右侧）。

### 阶段 5 · 昼夜四态

参考图右上角四张缩略图，标签条的实测位置为清晨 90–113、正午 200–228、黄昏 320–350、夜晚 443–462；
取样带必须避开它们（第一版就取到了标签条上，正午测出 30.9% 暖色、黄昏只有 2.8%，完全是错的）。

| 状态 | 参考图中景水 | 当前中景水 | 暖色占比（参考 / 当前）            |
| ---- | ------------ | ---------- | ---------------------------------- |
| 清晨 | `#6382a3`    | `#6284a3`  | 8.7% / 5.6%                        |
| 正午 | `#5a7898`    | `#5991b6`  | 8.2% / 3.3%                        |
| 黄昏 | `#584859`    | `#765f65`  | 34.2% / 40.5%                      |
| 夜晚 | `#294167`    | `#323d4d`  | 0.0% / 13.8%（余量主要为礁石本色） |

对照图见 `images/phase5-day-cycle.png`。

关键修正是**水面着色器原先完全不响应太阳高度**：天光反射是写死的蓝色梯度，所以黄昏水面几乎没有暖色（3.0%）。
现在水面与天空共用同一套 `sunsetAmount` / `nightAmount` 判据。过程中修掉三个问题：

1. **乘法染色压不过水色本身的蓝**。水色 B 远大于 R，红通道乘 1.3 也翻不过来，必须朝暖色混合。
2. **`sunsetAmount` 缺少地平线门控**，太阳落到地平线以下后它仍等于 1，导致夜色被染成紫红。
3. **天空着色器的地平线霞光叠加在夜景压暗之后**（既有 bug）：夜里地平线一直发橙，
   还会被水面掠射反射带上岸；夜晚中景一度有 47% 的暖色像素。已把霞光移到压暗之前。

另外入夜后太阳在地平线以下、镜面高光会整体熄灭，所以碎金光路的光源在夜里切换为月亮方向，
夜晚因此有了参考图那条月光路。

> 注意：本节所有对比都用"中景水"而非画面最底部的近景水。近景水天然更暗，
> 直接拿它和参考图的宽景缩略图比会把取样距离差异误判成画面偏暗（第一版就误判过清晨和夜晚）。

### 阶段 6 · 尾迹

旧实现由两部分组成：一张 58×106 的 V 形泡沫平面，外加 **22 片白色 ribbon**（标准材质、不受波场调制）。
后者在画面上就是船尾拖着两根粗白线，像绳子，和参考图的湍流尾迹完全不是一回事——已整体删除。

新实现：

- 尾迹泡沫与海面**共用同一套面片格**（`cellSize` + 网格原点偏移），所以泡沫按海面面片整片出现，
  能和浪脊白沫咬合，而不是叠出一条平滑白带；
- 顶点着色器传出的浪脊信号参与调制，浪脊上的尾迹泡沫更厚；
- 手臂加厚、噪声门控放宽，得到连续白带 + 碎边的形态，与参考图一致。

对照图见 `images/phase6-wake.png`。客观贡献：尾迹区域内亮部（明度>150）从 **18.3% → 22.9%**，平均明度 90 → 97。

**过程中修掉的碎金缺陷**：普通高光项 `spec` 原先**没有被楔形带门控**。它的波瓣很宽，
不门控会把暖色糊满整个下半屏，看起来像水里漂着大片米色斑块，而不是一条朝向太阳的光路。
现已与 `glint` 一起受 `band` 门控。

**方法上的教训**：本轮我一度根据截图预览判断"尾迹区有一片米色"，并据此追查了很久。
后来直接采样像素才发现该区域实际是深蓝水色（`#01305e`）配少量白沫——**是预览渲染让我看错了颜色**。
在此之前还误判过一次"尾迹太淡是因为被粗网格遮挡"（把 `wakeWaterOffset` 从 0.18 提到 0.7 毫无改善，假设被证伪）。

真正有效的办法是**隔离观察**：关掉海面白沫（`crestFoam: false`）与碎金（`highlightStrength: 0`），
尾迹的 V 形结构立刻一清二楚。当多个效果叠加、肉眼无法归因时，先做减法隔离，比反复调参有效得多。

### 阶段 7 · 近岸浅水与接触白沫

用一组「岛屿圆心 + 半径」在片元着色器里算到最近岸线的距离场，**不需要深度图或额外渲染目标**，
代价只是一个 8 次循环。由此得到两个效果：

- **近岸浅水**：越靠近岸线越浅，向薄荷青绿（`shallowColor`）过渡，再向外回到深蓝；
- **岸线白沫环**：紧贴岸线的一圈白沫，用 `step` 排除岛屿内部（负距离）以免白沫长到岛上。

网格与距离场**共用同一份 `ISLANDS` 数据**（原来 5 处岛屿位置散在调用点，现已集中定义），
岸线半径由圆柱底半径 9.5 米 × scale 推出，避免两边各写一遍而漂移。

## 追加 · 波场规律性修正（阶段 1~7 之后）

### 问题

大尺度观察时波浪仍然明显规律，尽管已经有「大 / 中 / 小」三层。

### 原因（有量化依据）

三层确实存在，但**每层内部只有 3 个正弦分量，且带内比例是固定有理数**（波长 1 : 0.64 : 0.41，
振幅 1 : 0.2 : 0.1）。用 `tools/wave-analysis.mjs` 算出的能量分布：

| 指标                       | 旧实现               |
| -------------------------- | -------------------- |
| 带内主分量占该带能量       | **91.2%**            |
| 全波场中最大单个正弦的占比 | **67.9%**            |
| 各带能量占比               | 74.5% / 24.3% / 1.2% |

也就是说「大中小三层」实际是**一个主导正弦 + 一个次要正弦 + 一点点装饰**：大尺度看到的
几乎就是一个 34 m 波长、14° 方向的单方向正弦波。而且三层之间自相似（同一套 1:0.2:0.1 比例，
只做尺度缩放），三层叠加反而在三个尺度上重复了同一种图案，强化了规律感。

`images/wave-regularity-diagnosis.png` 左图是旧波场的高度场（纯波形，非渲染），
规则的斜向条带与菱形干涉纹一目了然。

### 修正

`shaders.ts` 的 `evaluateOcean` 改为由 **CPU 侧 `buildWaveComponents` 生成分量表后整表传入**：

- 每带 8 个分量（共 24），波长按无理因子 1.3247 的幂铺开，消除有理比带来的空间周期性；
- 方向带散布，且短波散布更大（真实海面短波更受局地风扰动）；
- 谱形围绕带中心衰减（高斯窗），而不是「一个尖峰 + 两个小尾巴」——这正是能量集中的直接原因；
- 相位为确定性伪随机；速度按深水重力波 c ∝ √L 分布，取代原先固定 1.34 / 1.77 的速度比。

| 指标                   | 旧实现  | 新实现              |
| ---------------------- | ------- | ------------------- |
| 带内最大分量占该带能量 | 91.2%   | **27.1%**           |
| 全波场最大单个正弦占比 | 67.9%   | **20.1%**           |
| 高度 RMS               | 0.825 m | 0.826 m（能量守恒） |
| 均方坡度 Σk²a²         | 0.1154  | 0.1005              |

### 顺带修掉的两个既有问题

1. **CPU 与 GPU 的波场本来就是两份不同实现。** `sampleWave`（船体浮力用）用的是
   `sin(phase*2.07)`、`sin(phase*3.91)` 一套完全不同的谐波方案，而且没有平顶整形——
   也就是说船一直浮在**与渲染出的海面不一致**的高度上。现已合并为单一来源：
   分量表由 CPU 生成后，着色器与浮点采样共用同一份定义。

2. **浪脊信号「取带内最大值」会随分量数饱和。** 单分量 crest>0.5 占 17.6% 的周期，
   但 8 个分量取最大会变成 **79%** 的面积——白沫一度从 6% 涨到 31%。
   现改为「该带总高度 ÷ 该带均方根」，hn 的标准差恒为 1、与分量数无关。
   注意映射必须有界：hn 理论上可到 ±4，直接 `pow(hn*0.5+0.5, 8)` 会放大到上千。

### 一个排查中的教训

修正波形后我测得近景亮部从 6.0% 涨到 13.1%，一度以为是新波形让海面变亮，先后排查了
菲涅尔反射、高度调色、明暗对比、次表面透光、碎金——**逐项关掉都几乎没变化**。
最后才发现真正原因是**阶段 6 加密过的尾迹**：关掉尾迹后亮部立刻从 13.1% 掉到 3.7%。
而 6.0% 那个基线是在阶段 6 之前测的，两者本就不可比。

**多个效果叠加时，先做减法隔离再归因**——这一点在阶段 6 已经吃过一次亏，这次又踩了一遍。

## 附录 · 浪尖白沫与近岸浅水的实现原理

中间信号分解图见 `images/foam-and-shallow-pipeline.png`（与渲染同一套公式）。
两者**都是纯解析的**：不需要深度图、不需要离屏渲染目标、不需要预烘焙贴图。

### 浪尖白沫（5 步）

1. **逐带累加高度**：顶点着色器里 24 个波分量按「所属波带」分三组累加高度 → `bandHeight` (vec3)。
2. **归一化**：除以该带的均方根 `waveRms` → `hn`。这一步让统计量与分量数无关
   （hn 的标准差恒为 1），否则分量数一变白沫覆盖就会跑偏。
3. **有界锐化**：`crests = pow(clamp(hn*0.3 + 0.5, 0, 1), 8)`，每条带一个 [0,1] 的浪脊强度。
   8 次幂让「接近浪尖」变得很尖锐，`clamp` 保证不会像无界版本那样放大到上千。
4. **加权取最大**：片元里 `foamSignal = max(crest_i * weight_i - bias_i) + 高度项 + 坡度项`。
   三个 `weight` / `bias` 就是面板上的「大波 / 中波 / 小波阈值」。
5. **块状化与着色**：
   - 用**面片 ID** 扰动阈值得到 `blocky`——白沫边界因此沿面片走，而不是 fbm 那种细碎丝状噪声；
     这是面片 ID 量化（阶段 1）的第二次使用；
   - 再用**细一档的量化格**（`cellSize × 0.32`）撒碎晶白点，尺度由面片尺寸决定，远处不会糊成一团；
   - 最后按受光 / 背光两档着色：受光面趋近纯白、背光面略冷略暗。
     白沫是自发漫反射白体，**不能按面法线压暗**，否则倾斜浪脊上的白沫会变成土黄色块。

### 近岸浅水与岸线白沫（3 步）

1. **岛屿数据在 CPU 集中定义**（`ISLANDS`），以 `(圆心x, 圆心z, 岸线半径)` 打包成 uniform 数组传入。
   岸线半径 = 圆柱底半径 9.5 米 × scale，与岛屿网格同源，不会漂移。
2. **片元里求岸线距离场**：对 8 个岛屿算 `distance(世界xz, 岛屿xz) - 半径` 取最小值。
   负值表示在岛上。代价只是一个 8 次循环。
3. **两件事同时用这个距离**：
   - **浅水**：`1 - smoothstep(shallowStart, shallowEnd, max(0, d))` → 混合系数，
     把水色朝 `shallowColor`（薄荷青绿）混合 85%。范围由面板「浅水范围 m」控制（默认 18 m）；
   - **岸线白沫环**：`1 - smoothstep(0, 3.4, max(0, d))`，再乘 `step(-2.5, d)` 排除岛屿内部；
     用与浪尖白沫相同的 `foamLit` 混合，两者观感一致。

> 已知近似：岛屿网格是圆柱底，所以浅水环是**正圆**。参考图的岛屿若是不规则形状，
> 需要换成有符号距离场贴图才能贴合岸线。

## 追加 · 白沫判据：参考实现的做法与一次未完成的移植

### 参考实现（Babylon FFT Ocean 官方 demo，仓库内已有其移植）

那份移植就在 `src/engine/babylon/fftOcean/`，白沫相关代码完整。它的做法是：

1. **判据是位移的雅可比行列式（折叠度），不是高度极大值。**
   `wavesTexturesMerger.wgsl`：
   ```wgsl
   let jacobian = (1.0 + Lambda*DxxDzz.x) * (1.0 + Lambda*DxxDzz.y)
                - Lambda*Lambda*DyDxz.y*DyDxz.y;
   ```
2. **时间累积 + 衰减 —— 白沫"记忆"的来源。**
   ```wgsl
   var turbulence = textureLoad(TurbulenceRead, iid.xy, 0).r
                  + params.DeltaTime * 0.5 / max(jacobian, 0.5);
   turbulence = min(jacobian, turbulence);
   ```
   `min` 让白沫在折叠瞬间立即出现，加法让它随后缓慢消散。
3. **高度与坡度只是微小修正。** `_FoamHeightWeight = 0.04`、`_FoamSlopeWeight = 0.08`，
   而主项是 `(-turbulence + bias) * weight`。
   **我们的移植把这两个辅助项的数值搬了过来，却让它们当了主项**——这是白沫观感粗糙的根源。
4. 破碎纹理用 `public/assets/fft-ocean-foam.jpg`（该素材已在仓库里）。
5. 船尾航迹与岸边白沫用的是**深度缓冲**（`backgroundDepth - surfaceDepth`），不是独立的尾迹平面。

### 我们的解析波场可以直接算这个雅可比

对解析 Gerstner 和，`shaped` 的二阶导可直接写出：
`shaped''(p) = -nrm · s · (D + 3p²c²) / D^{2.5}`，`D = 1 + p²s²`，
于是 `J = (1+Σ qk·d_x²·shaped'') (1+Σ qk·d_z²·shaped'') - (Σ qk·d_x·d_z·shaped'')²`，
其中 `qk = k·振幅·水平挤压·chop·0.34`。

实测我们的 J 分布（默认参数）：

| 分位                             | 值                    |
| -------------------------------- | --------------------- |
| 最小 / p1                        | 0.767 / 0.864         |
| 中位数 / p90 / 最大              | 0.999 / 1.079 / 1.247 |
| P(J<0.9) / P(J<0.95) / P(J<0.97) | 4.7% / 20.8% / 31.5%  |

注意：`Σq ≈ 0.2` 那个小振幅近似（`J ≈ 1 − Σq·sin`）**是错的**——平顶整形让二阶导在过渡段远大于正弦。
参考实现的阈值（0.84 / 0.89 / 0.99）是按它自己的波陡度定的，我们必须重新标定。

### 已落地：折叠度判据（瞬时版）

白沫主项已从「波带高度极大值」换成**位移雅可比（折叠度）**，在顶点着色器里解析求值：

```glsl
float foldFoam = clamp((foamFoldBias - vFold) * foamFoldScale, 0.0, 1.0);
```

面板新增「折叠阈值」（默认 0.90）。实测：

| 指标     | 参考图 | 当前     |
| -------- | ------ | -------- |
| 明度>190 | 6.2%   | **7.1%** |
| 明度>235 | 2.4%   | **2.5%** |

对照图见 `images/foam-jacobian-vs-height.png`：白沫形状从圆形斑块变成**沿浪脊拉长的条带**。

代价：顶点着色器多一次 24 分量的雅可比求值（约 +1 倍 `sin/cos`），实测帧率无可见影响。

### 打通 RTT 时发现的两个坑（记录备查）

1. **采样器名不能同时出现在 `ShaderMaterial` 的 `uniforms` 数组里。**
   必须只靠 `setTexture()` 注册（它会自动加入 `_options.samplers`）。
   放进 `uniforms` 会导致采样器**完全不绑定**，`texture2D` 恒返回黑色。
   这个问题用一张普通图片贴图 + 固定 UV 采样做了决定性验证（HTTP 200、442 KB、已加载，采样仍为纯黑），
   排查时先后误怀疑过 RTT 构造参数、`customRenderTargets`、嵌套渲染、layerMask、专用相机。

2. **`RenderTargetTexture.render()` 在本项目里不产生任何输出**（连 `clearColor` 都没生效），
   而 `material.isReady()` / `mesh.isReady()` / `renderList` / `isEnabled` 全部正常。
   这一条尚未定位到根因，因此时间累积改走了另一条路（见下）。

### 时间累积：改用解析历史采样，绕开渲染目标

解析波场是时间的确定性函数，历史可以随用随算——在顶点着色器里回采若干过去时刻的雅可比，
取衰减后的最小值：

```glsl
for (int k = 0; k < 4; k++) {
  float past = time - float(k) * foamHistoryStep;
  turbulence = min(turbulence, evaluateJacobianAt(base, past) + float(k) * foamHistoryStep * 0.5);
}
```

这与参考实现的 `min(jacobian, prev + dt·0.5/max(jacobian,0.5))` **语义等价**：
min 让白沫在折叠瞬间立即出现，随时间的加法让它缓慢消散。代价是 4 倍雅可比求值
（顶点着色器从 24 分量位移 + 24 分量雅可比，变成 + 96 分量）。

### 一个方法论教训

本轮我用「动画运行时相邻两帧的画面差异」验证时间累积，得到「有记忆 2.65 / 无记忆 2.58」——
**这个指标根本不可用**：画面差异被水面自身运动主导，白沫的持久性淹没在里面。
更早一次 A/B 同样无效（我用 `window.__step` 设值，但那个变量从未接到着色器上，两次跑的是同一配置）。
**下结论前先确认测量手段真的能区分两种配置**，否则只是在读噪声。
**下一步**：定位 `RenderTargetTexture.render()` 不出图的原因（建议最小复现），
接上时间累积后白沫就会有"厚实、破浪后残留"的质感——这是参考实现观感的最后一块拼图。

## 追加 · 海天交界的硬边

### 真正的原因

不是雾色不准，而是**海面平面的边缘本身就在可见范围内，而且雾没盖住它**：

| 平面边缘距相机    | 该处的雾强度 |
| ----------------- | ------------ |
| 230 m（朝 -z 看） | **20%**      |
| 470 m（朝 +z 看） | **67%**      |

海面是 700×700 米、相机在 z=-120，所以边缘只有 230~470 米远；雾 130→640 米，
在边缘处远未饱和。**那条"硬边"就是海面的物理边缘。**

实测水面到相机的距离分布也证实了这点：画面最远处的水面约 300 米，再往上就是天空。

### 已做的改动

1. **把天空的颜色计算抽成共享函数 `skyBaseColor`**，天空着色器与海面着色器调用**同一份**。
   在此之前海面用的是手写的近似公式（只取了 horizon 项，漏掉了天顶渐变与霞光），
   算出来的颜色比天空亮，怎么调都对不上。
2. 远处水面按"视线是否接近水平"融进天空的地平线颜色，作为边缘的兜底。

3. **渐隐范围按"到平面边界的距离"自适应**（关键一步）。
   固定阈值不行——相机一升高，平面边缘又落到未虚化的区域里。现在按视线方向解析算出
   到平面边界的距离，在到达边界之前就把水面完全变成天空色，
   于是**边缘本身一定落在已经虚化完的区域里**，与相机高度、朝向都无关。

   注意实现细节：不能用 `sign(planarDir)` 求边界方向——分量为 0 时 `sign` 返回 0，
   会算出 `0/0 = NaN` 让整个混合失效（表现为整片海变成天空色）。

对照见 `images/horizon-fade.png`：硬边消失，过渡为渐变。低机位与高机位均已验证。

### 与"把海面做大"的关系

自适应渐隐已经把边缘藏住了，所以**放大海面不再是为了消除硬边**，而是为了视野更开阔、
以及让雾有空间铺开。放大时仍需一并处理面片尺寸：

- 海面放大到 3000 m 以上
- 雾终点相应推到 1200 m 以上（否则远处全是白雾，海面放大也没意义）

这正是你提的"海面要大一点"。但要一并处理面片尺寸问题：现在 700 m / 512 细分 = 1.37 m 面片，
若直接放大到 3000 m 而不加 LOD，面片会变成 5.9 m，明显变粗。

### 一条方法论教训

本轮我的量化测量**自相矛盾**：换一个采样窗口，地平线跳变就从 23 变成 29；
而调试图里的"灰阶读数"被 ACES 色调映射压过，读到的 0.6 实际可能是 0.9。
**在色调映射之后的画面上反推线性量是不可靠的**，这类判断应当以同一机位、同一窗口的
视觉 A/B 为准。

## 追加 · 天光反射（"水面看不到倒影"）

### 先澄清：不是材质的问题，是**场景里没有反射源**

改动前，水面着色器里的所谓"反射"是这段：

```glsl
vec3 reflectedSky = mix(..., clamp(normal.y*.62+.22, 0, 1));
```

这是**按法线和昼夜写死的两色渐变**，不是反射。而且场景里既没有环境贴图、没有反射探针、
没有镜面反射纹理、也没有 SSR——**没有任何人渲染过"被反射的那幅画面"**，材质无从反射。

### 已做：按反射方向求真实天空色（零额外渲染）

复用与天空共享的 `skyBaseColor`，在**反射方向**上求值：

```glsl
vec3 reflectDir = reflect(-viewDir, normal);
vec3 reflectedSky = pow(clamp(skyBaseColor(reflectDir, ...) * skyLuminance, 0.0, 1.0), vec3(.92));
```

天顶渐变、太阳位置、日落色温因此都出现在正确的地方，**不需要任何额外渲染通道**。
对照见 `images/sky-reflection.png`。

### 两个让它"看不见"的原因（都已修）

1. **反射权重被多乘了一个 0.46。** 旧代码是
   `mix(water, reflectedSky, fresnel*(.42+roughness*.22))`——那个 `(.42+roughness*.22) ≈ 0.46`
   是为**写死的假渐变**调的。反射变成真的之后再乘它，等于把强度砍掉一半多。
   现在直接用菲涅尔反射率，仅保留轻微的粗糙度衰减。
   实测菲涅尔在 30/100/300 m 处分别是 0.16 / 0.54 / 0.76——物理上掠射角反射本来就该这么强。

2. **水体的昼夜染色盖住了反射。** 这两行
   ```glsl
   water=mix(water,vec3(.12,.09,.13),sunsetAmount*.7);   // 夕阳去饱和
   water=mix(water,vec3(.16,.26,.46),nightAmount*.55);   // 入夜偏蓝
   ```
   原本排在反射**之后**，会把刚混进去的天光整个盖掉。它们描述的是"水本身"的颜色，
   已移到反射之前。

> 排查记录：把反射权重强制设为 1.0 后水面呈 (65,50,70) 的暗紫——说明反射算出来了、
> 但被后续步骤覆盖。**用"强制满值"来区分"没算"和"被盖住"**，比反复调参数有效得多。

### 局限：反射的是天空，不是物体

这一步反射的只有天空（以及太阳）。**岛屿、船这些具体几何不会出现在倒影里**——
那需要真正的反射源。可选：平面镜面反射（`MirrorTexture`，位置准确但要每帧多渲一遍场景，
且要把水面自身排除以免无限递归）、反射探针（便宜但近距离倒影位置会飘）、SSR（屏幕外反射不出来）。

另：参考图里水面的倒影本来就以天空与太阳为主，岛屿倒影很弱，掠射角下水面反射本就以天空为主。
