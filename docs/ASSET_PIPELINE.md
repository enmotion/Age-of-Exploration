# 美术资产生产流

目标是让每一项模型、贴图、动画、HDRI、音频和着色器都能回答四个问题：源文件在哪里、能否商用、怎样变成 Web 资产、超出预算时由谁发现。

## 当前流程

```text
Blender / 开源资产平台 / 自制贴图
  → assets/vendor 或 assets/source（原始文件和许可）
  → assets/catalog.json（来源、许可、预算、变换）
  → npm run assets:build（GLB 内嵌纹理 + Meshopt）
  → public/assets（仅运行时文件）
  → npm run assets:validate（glTF 规范 + 体积 + 溯源）
  → Vite Web 构建
```

`npm run build` 强制执行资产校验。运行时通过 `src/engine/assets/modelAssets.ts` 延迟加载并缓存 GLB，场景实例从缓存克隆。主船加载失败时保留程序化船体，所以单个素材故障不会阻断航行。

## 新增模型

1. 确认许可允许商用、修改和再分发。把原始许可与来源说明保存在素材目录；来源不明确的文件不进入项目。
2. 在 Blender 中统一为 Y 轴向上、米制单位、原点靠近接地点，并应用缩放。网格、骨骼、动画和材质使用稳定英文名称。
3. 导出 glTF 2.0 的 GLB。贴图使用 2 的幂尺寸；Base Color 和 Emissive 为 sRGB，其余数据贴图保持线性空间。
4. 在 `assets/catalog.json` 登记唯一 ID、源路径、输出路径、Web URL、来源、许可和体积上限。
5. 运行 `npm run assets:build && npm run assets:validate`，再在浏览器检查比例、朝向、水线、动画和移动设备显存。

## 贴图、着色器与动画

- 当前色板贴图在生成 GLB 时已被内嵌。写实素材应采用 PBR 的 Base Color、Normal、ORM（Occlusion/Roughness/Metallic）组合，并控制每个风格包的纹理集合。
- KTX2/BasisU 是纹理显存优化目标；安装 `toktx` 后，将高分辨率 PBR 贴图切换为 KTX2。发布前要保留 WebP/PNG 或低规格材质作为不支持场景的降级方案。
- 项目级海面、天空和天气 Shader 放在 `src/engine/three`，可复用材质节点放在 `src/engine/materials`。每个 Shader 应有低、中、高三档参数，避免把设备性能差异写进游戏规则。
- 动画统一在 GLB 中按动作拆分 clip，例如 `idle`、`walk`、`talk`、`work`。导入后使用 `AnimationMixer`；人物模型优先共享骨架与动作库，避免每个 NPC 单独制作整套动画。

## 素材来源策略

- 第一优先级是自制核心识别资产：主船、重要 NPC、关键港口地标。
- 第二优先级是许可清晰的 CC0 素材，用于桶、箱、码头、岩石和环境填充。当前基线来自 Kenney Pirate Kit 2.1。
- HDRI 与通用 PBR 材质可从 Poly Haven 获取，并逐项记录具体资产 URL；不能把网站预览图、Logo 当作 CC0 素材。
- 付费商店素材必须保存订单和许可快照，并确认是否允许随 Web 包分发。不能确认时只保存采购候选链接。

## 建议工具

- Blender：建模、UV、骨骼、动画、碰撞体和 glTF 导出。
- glTF Transform：去重、合批、纹理内嵌与 Meshopt 压缩，项目已安装。
- Khronos glTF Validator：结构校验，项目已安装并接入构建。
- `toktx`：KTX2/BasisU 转码，后续安装系统工具时接入。
- Krita、GIMP 或 Substance 3D：贴图绘制与烘焙；核心流程不依赖某一家付费软件。

当前导入的是风格统一的低多边形 CC0 基线，用来证明生产流和替换机制。更写实的主船可沿用同一个资产 ID 替换，不需要修改航海规则、UI 或存档结构。

## 当前海岛环境

`src/engine/three/environment/` 保存原创、可重复生成的环境源代码：

- `island.ts`：确定性地形、沙滩顶点色、礁石，以及实例化的树干、树冠、灌木和棕榈叶。叶片通过顶点 Shader 摇动，无需下载植被贴图。
- `atmosphere.ts`：共享大气颜色、太阳/月亮、分层移动云与星空。
- `ocean.ts`：多方向波浪、局部加密网格、微表面法线、浅水色、岸边泡沫和低分辨率平面反射。几何与反射缓冲在场景销毁时释放。
- `waves.ts`：CPU/GPU 共用的四组波形参数，包含尖浪峰与宽浪谷。海面位移、逐像素法线、船体浮动和尾迹高度使用同一组波形，避免各自手调造成错位。
- 远海白沫由浪峰叠加程度与破碎纹理驱动；延迟波形采样近似破浪后约 1.5 秒的残留，纹理随低速表面漂移，并在远处淡出。它是无额外模拟缓冲的视觉近似，不是流体或泡沫粒子仿真。
- `dayCycle.ts`：独立于经济/航海时钟的视觉昼夜。1× 为两分钟一昼夜，也可加速或定格光照。
- `nightLights.ts`：两盏船灯、八支岸边火把、程序化光晕与跳动火焰。使用四个不投射阴影的局部点光源，入夜渐亮；海面单独计算暖光与碎波高光。灯具跟随船只和岛屿变换，卸载时释放共享材质、几何与光晕纹理。

银河由天空 Shader 的倾斜星带、星群及暗尘噪声生成，夜间减少云层覆盖。银河与灯火复用已有平面反射，不增加额外反射通道；手机 GPU 性能仍需实机测量。

这组程序化源码本身就是可编辑的生产源件，不需要额外 Blender/MCP 才能重新生成。它们不经 GLB 压缩流程；随 Web 代码构建发布，通过 `npm run test:visual` 验证 Shader 编译、昼夜和交互。第三方船体继续沿用上面的 GLB 素材流水线。

### 天空与海面素材（2026-09-08）

银河使用 AI 生成的星空原图，保留于 `assets/source/sky/`；完整提示词与来源见该目录的 `PROVENANCE.md`。`npm run assets:build` 输出约 534 KiB 的 WebP，发布校验限制为 1.5 MB。夜空按太阳高度淡入，银河天区边缘做淡出；它是艺术化背景，不是天文全天球数据。

云层以八层密度累积近似厚度与透光，降低黄昏明暗反差；海面采用六组不同方向、波长与弯曲相位的波浪，CPU 浮力与 GPU 水面共享系数，波峰交会处生成稀疏浪沫。云层仍是轻量近似，并非完整体积云模拟。
